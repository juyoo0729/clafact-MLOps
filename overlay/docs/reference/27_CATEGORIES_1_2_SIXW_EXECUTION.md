## 1. 목적

`CLAFACT_1-8분류_문제와해결책.txt`의 다음 두 유형을 전체 기사 문맥과 연결해 실제로
실행하고, 성공과 실패를 Claim 단위 육하원칙으로 남긴다.

1. 문맥 보완 필요
2. 복수 Claim 분리 필요

이 실행의 성공은 문맥 기간 복원 또는 안전한 원자 Claim 분리 성공이다. KOSIS 공식값
확보나 사실 판정 성공을 뜻하지 않는다.

## 2. 실행 범위와 건수 차이

설명 TXT에는 1번 258건, 2번 339건으로 적혀 있다. 그러나 최신 1,542건 분류 원장과
전체 기사 감사 원장에는 1번 256건, 2번 339건이 존재한다. 따라서 실제 실행 범위는
597건을 억지로 맞춘 값이 아니라 고유 Claim 595건이다.

| 구분 | TXT 선언 | 최신 실제 | 차이 |
|---|---:|---:|---:|
| 1번 문맥 보완 | 258 | 256 | -2 |
| 2번 복수 Claim | 339 | 339 | 0 |
| 합계 | 597 | 595 | -2 |

입력은 499개 전체 기사와 1,542개 Claim을 연결한
`full_article_audit_20260825_v2/claim_audit_1542.csv`다. 1번 256건은 모두 기사 본문에서
원문이 정확히 연결되고 작성일도 존재했다.

## 3. 1번 문맥 보완 실행 규칙

기간 변환기는 기사 작성일을 기준으로 `지난달`, `이달`, `올해 들어`, `올해`, `작년`,
`지난해`, `1~20일`, 명시 연·월을 표준 기간으로 바꾼다.

안전 기준은 다음과 같다.

- Claim 자체의 상대기간을 먼저 사용한다.
- 앞·뒤 문맥이 같은 목표기간을 가리키면 성공시킨다.
- 한쪽 문맥에 절대연도만 있으면 Claim과의 의미 연결이 불충분하므로 부분성공으로 둔다.
- 앞·뒤 문맥의 기간 후보가 다르면 `MULTIPLE_CONTEXT_PERIODS_UNRESOLVED`로 HOLD한다.
- `작년 … 2023년 대비`처럼 목표기간과 비교기간이 함께 있으면 각각 2024년과 2023년으로
  분리한다.
- 전면 재해석이나 누락 슬롯의 구조화가 더 필요하면 기간 후보가 있어도 성공으로
  과대보고하지 않는다.

## 4. 2번 복수 Claim 분리 실행 규칙

기존 `rule_ensemble` 분리기를 실행한 뒤 다음 검사를 추가한다.

1. 부모 원문의 모든 수치가 자식 Claim에 정확히 한 번씩 보존됐는가?
2. 각 자식 Claim에는 검증 대상 수치가 정확히 하나 있는가?
3. 목표 수치가 부모 원문에 실제로 존재하는가?
4. 자식이 2개 이상이고 분리 경로가 `AUTO`인가?

네 조건을 모두 만족한 부모만 `ATOMIC_SPLIT_VALIDATED` 성공으로 기록한다. 자식 하나가
개별적으로 `VALID`여도 부모 전체 분리가 HOLD라면 KOSIS 재투입 대상에는 포함하지 않는다.

## 6. 육하원칙 기록

부모와 자식의 모든 실행을 합쳐 992개 이벤트를 남긴다.

- 누가: 기사번호, 부모·자식 Claim 번호
- 언제: 기사 작성일, 실행 시각
- 어디서: 기사 URL, 본문 위치 또는 부모 Claim
- 무엇을: 복원한 기간 또는 분리한 목표 수치
- 어떻게: 문맥 연결·기간 변환 규칙 또는 분리·수치 보존 검사
- 왜: 성공/HOLD reason code

각 이벤트에는 중단 단계, 입력·출력 요약, KOSIS 재조회 상태도 함께 기록한다.
