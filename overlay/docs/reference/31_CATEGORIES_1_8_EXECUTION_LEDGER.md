# Claim 검증유형 1~8 전체 실행 원장

## 1. 목적

이 실행은 `CLAFACT_1542_검증유형별_재분류_완성본.xlsx`의 1,542개 Claim을 검증유형
1~8의 서로 다른 Evidence 요구사항으로 다시 라우팅한다. 목표는 통과 수를 부풀리는 것이 아니라
각 Claim에 다음 내용을 한 줄의 불변 실행기록으로 남기는 것이다.

- 어떤 유형과 Claim을 누가·언제·어디서 처리했는가
- 어떤 검증 방법과 공식값 범위를 요구했는가
- KOSIS 메타데이터·값 단계에 어디까지 도달했는가
- 어느 단계에서 어떤 이유로 멈췄는가
- 다음 실행에서 무엇을 보완해야 하는가

이 작업은 저장된 기사 문맥 감사표, 저장된 KOSIS 조회 결과, 1·2번 다중방법 결과와 20건
12-slot 재진입 파일을 결합한 오프라인 재현 실행이다. 신규 provider 호출과 신규 KOSIS 호출은
모두 0건이다.

## 3. 1·2번 보완 내용

1번의 문맥 보완 성공은 KOSIS 성공이 아니다. 문맥에서 기간을 확정한 Claim은 다시 12-slot
구조화로 보내고, 문맥이 여러 기간으로 갈리거나 지표·대상이 남아 있으면 HOLD로 보존한다.

2번은 문장 단위 분리 대신 숫자별 `target_value_role`을 가진 원자 자식 Claim을 전제로 한다.
부모의 숫자·단위가 자식에 잘못 섞이지 않도록 원문 숫자 포함 여부와 부모-자식 숫자 커버리지를
통과한 경우만 12-slot 재진입 대상으로 삼는다.

두 유형은 Claim 내용이 바뀌므로 과거 부모 Claim의 공식값 10건을 새 Claim의 근거로 재사용하지
않았다. 전체 공식 조회는 새 12-slot과 목표 숫자 역할이 확정된 뒤 별도 실행해야 한다.

## 4. 3~8번 유형별 안전 규칙

| 유형 | 계산 | 한 값만 확보했을 때의 처리 |
|---:|---|---|
| 3 | `min`/`max`와 해당 기간을 함께 계산 | 전체 기간이 아니므로 `PARTIAL_SUCCESS` |
| 4 | 동률을 보존하는 경쟁 순위 계산 | 전체 비교 대상이 아니므로 `HOLD` 또는 `PARTIAL_SUCCESS` |
| 5 | `분자 / 분모` | 분자·분모가 모두 없으면 최종 계산 금지 |
| 6 | `현재값 - 비교값` | 한 값만 있으면 `ADDITIONAL_EVIDENCE_VALUES_REQUIRED` |
| 7 | `(현재값 - 비교값) / 비교값 * 100` | 두 값과 0 분모 검사가 끝나기 전 계산 금지 |
| 8 | 기사값과 공식값 직접 비교 | 기사 당시 공표값과 `target_value_role` 확인 전 최종 판정 금지 |

공식값을 찾았다는 사실은 Claim이 맞다는 뜻이 아니다. 모든 유형에서 좌표의 지표·지역·기간·단위가
Claim과 일치해야 하며, 최종 판정은 기사 당시 사용 가능했던 값과 독립 Gold가 연결된 경우에만
평가할 수 있다.

## 6. 실행기록 계약

`tools.build_claim_categories_1_8_execution`은 Claim마다 다음 필드를 기록한다.

- 실행 배치와 UTC 시각
- 유형, Evidence 계획, 요구 범위, 요구 공식값 수
- 실행 상태, 중단 단계, 사유 코드, 다음 작업
- KOSIS 도달 상태, 공식 좌표 상태와 좌표
- 공식값·단위, 응답 SHA-256, 근거 경로
- 기사시점 공표 검사와 목표값 역할 검사 상태
- 육하원칙 기록과 행별 결과 SHA-256

결과 디렉터리는 비어 있어야 하며, 기존 산출물을 덮어쓰지 않는다. 기사 원문, API 키, 원시 API
응답은 저장하거나 출력하지 않는다.

## 7. 평가 결론과 다음 순서

현재 정확도 결론은 `NOT_EVALUABLE_NO_LINKED_CATEGORY_SPECIFIC_GOLD`이다. 1,542건 전체 실행과
공식값 연결률은 운영 coverage이며, 정확도나 KOSIS 정답률이 아니다.

다음 실행은 전체 1,542건을 무조건 다시 호출하지 않는다.

1. 1·2번 성공 Claim을 새 12-slot과 `target_value_role`로 재구성한다.
2. 3~7번은 한 좌표의 필요한 비교 범위를 묶어서 조회한다.
3. 8번은 기사 작성일 기준 공표 이력과 목표 숫자 역할을 검사한다.
4. 동일 Claim ID에 유형별 독립 Gold를 연결한 뒤에만 계산과 Verdict 정확도를 평가한다.

이 순서가 KOSIS 통과 규칙을 약하게 만들지 않으면서 실제 통과 가능한 Claim을 늘리는 방법이다.
