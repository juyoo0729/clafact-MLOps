# Claim 1~8번 실험 과정과 발표 근거

## 발표 결론

이 작업의 결과는 “1,542건 자동 판정 완료”가 아니다. Claim 유형마다 필요한 Evidence 범위를
가설로 세우고, 같은 입력에서 통과 규칙을 낮추지 않은 채 모든 성공·부분 성공·HOLD의 중단 단계와
이유를 기록했다. 완성도보다 재현 가능한 문제 해결 과정을 발표 근거로 사용한다.

## 고정 입력과 측정 경계

- 통합 엑셀 고유 Claim: 1,542건
- 기사 문맥 정확 조인: 1,542건
- 저장 registry 정확 조인: 1,542건
- 전체 라우팅의 신규 provider/KOSIS 호출: 0건
- Gold 변경: 없음
- 정확도: `NOT_EVALUABLE_NO_LINKED_CATEGORY_SPECIFIC_GOLD`

통과 건수와 공식값 연결 건수는 운영 coverage다. 같은 Claim ID의 독립 Gold가 없는 정확도,
Hit@k, Evidence 좌표 exact, Verdict 정확도는 계산하지 않는다.

## 실험 A: 1·2번 Claim 구조화

### 문제와 가설

문맥 의존 Claim과 여러 숫자가 섞인 Claim이 하나의 규칙으로 처리되지 않았다. 기존 성공은
보존하고 HOLD만 다음 방법으로 전달하면서 모든 방법에 같은 결정론적 안전검사를 적용하면,
규칙을 약하게 만들지 않고 구조화 coverage를 높일 수 있다고 가정했다.

### 단일 변경

6개 규칙과 두 구조화 모델을 순차 적용하는 fail-closed cascade를 추가했다. 원문 수치 존재,
부모 수치 보존, 자식별 목표값, 기간 근거와 정규화가 모두 맞을 때만 결과를 채택했다.

### 같은 Claim에서의 변화

| 유형 | 전 | 후 |
|---|---|---|
| 문맥 보완 | 성공 126, 부분 34, HOLD 96 | 성공 136, 부분 34, HOLD 86 |
| 복수 Claim | 성공 30, HOLD 309 | 성공 235, HOLD 104 |

안전 자식 Claim은 627건이었다. 그러나 문맥 보완 HOLD에 HCX를 추가 적용한 시도는 신규 성공
0건이므로 `NOT_IMPROVED`로 남겼다. 기사에 근거가 없으면 모델 추가만으로 해결되지 않는다는
실패 증거다.

## 실험 B: 20건 12슬롯 재진입

### 문제와 가설

Claim 구조화 성공은 KOSIS 진입 성공이 아니다. 기사 작성일과 인접 문맥을 함께 전달하고,
필수 슬롯·원문 숫자·기간·`target_value_role`을 독립 규칙으로 재검사하면 안전한 R3_READY만
분리할 수 있다고 가정했다.

### 결과

- 고정 표본 20건, provider 시도 20건, 오류 0건, 재시도 0건
- R3_READY 4건, HOLD 16건
- HOLD 원인: 문맥 충돌 8, 구조 출력 비자동 승인 3, 원문 값 추적 실패 3, 목표값 역할 불일치 2
- KOSIS 호출 0건

1·2번 구조화 성공 371건을 KOSIS 성공으로 과대보고하면 안 된다는 근거가 됐다.

## 실험 C: 유형별 Evidence 라우팅

### 문제와 가설

공식값 하나를 찾았다는 공통 조건은 계산형 Claim을 잘못 완료시킬 수 있다. 최고·최저는 전체
기간, 순위는 전체 비교 대상, 비중은 분자·분모, 증감량과 증감률은 두 기간 값이 필요하다.
유형별 완료 조건을 먼저 고정하면 공식값 coverage와 최종 판정 가능 상태를 분리할 수 있다고
가정했다.

### 단일 변경

1~8번 유형별 Evidence 계획과 fail-closed 라우팅을 추가했다. 직접값도 기사 당시 공표 상태와
목표 숫자 역할 확인 전에는 최종 판정하지 않는다.

### 결과

| 상태 | 건수 |
|---|---:|
| R2 단계 성공 | 371 |
| R2 단계 부분 성공 | 34 |
| 공식근거 부분 성공 | 101 |
| HOLD | 1,032 |
| 사전 제외 | 4 |

저장된 공식값 101건을 연결했지만 최종 Verdict 준비 완료는 0건이다. 1·2번의 과거 공식값
10건은 변경된 Claim에 재사용하지 않았고, 과거 `AUTO` 27건은 필수 Evidence가 없어 안전하게
다시 라우팅했다. 완성 건수는 늘지 않았지만 과대 AUTO를 방지했다.

## TDD 기록

1. 유형별 Evidence 모듈이 없다는 새 테스트를 먼저 작성했다.
2. 첫 테스트는 `ModuleNotFoundError`로 실패했다.
3. 유형별 계획과 최소 라우팅 구현을 추가했다.
4. 단일값으로 계산형 Claim을 완료하지 않는지, 직접값에도 기사시점과 숫자역할 검사를 요구하는지,
   사전 제외를 되살리지 않는지를 고정했다.
5. 신규 관련 테스트 5개가 통과했다.
6. 실제 입력을 포함한 병합 환경에서 전체 회귀시험 888개가 통과했다.
