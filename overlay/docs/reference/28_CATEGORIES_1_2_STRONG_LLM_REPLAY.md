# 1번·2번 강한 2차 재실행

## 1. 왜 기존 방식만으로 부족했는가

1차 실행은 실패를 숨기지 않는 원장으로는 충분했지만 HOLD를 풀어내는 해석기가 약했다.

- 1번 문맥 보완: 성공 126, 부분성공 34, HOLD 96
- 2번 복수 Claim 분리: 성공 30, HOLD 309

특히 2번은 공유 서술어 83건, 규칙상 단일 Claim 182건, 문맥 필요 27건이 큰 묶음이었다.
1번은 앞·뒤 문맥 기간 충돌 66건이 가장 컸다.

강한 방식은 통과 기준을 느슨하게 만드는 것이 아니다. 규칙이 해결하지 못한 Claim에만
구조화 LLM을 한 번 사용하고, 제안 결과를 결정론 검증기가 다시 거부할 수 있게 만드는
방식이다.

## 2. 2번 강화 방법

처리 순서는 다음과 같다.

1. `rule_ensemble`을 다시 실행한다.
2. 규칙 검증이 HOLD인 Claim만 OpenAI strict structured output으로 재분리한다.
3. 각 자식은 목표 수치 하나만 가져야 한다.
4. 목표 수치는 부모 원문에 실제로 존재해야 한다.
5. 부모 수치는 자식 전체에 빠짐없이 보존돼야 한다.
6. `각각 …씩`처럼 하나의 수치가 여러 대상에 명시적으로 재사용되는 경우만
   `CONTROLLED_RESPECTIVELY_REUSE`로 허용한다.
7. 모든 검사를 통과한 LLM 후보만 최종 결과로 채택한다.

숫자 파서는 다음 표현을 추가로 보존한다.

- 부호: `-0.8%포인트`, `-19.2%`
- 근사 범위: `92%대`, `10만명가량`, `20%안팎`
- 명시적 각각 재사용: `2017년 1~2월 각각 0.2%포인트씩`

모델 호출은 Claim마다 최대 한 번이며 자동 재시도는 없다. API 오류가 발생하면 기존
HOLD를 유지한다.

## 3. 1번 강화 방법

1번에서는 기존 성공 126건은 다시 호출하지 않았다. 다음 사유만 강화 후보로 삼았다.

- 문맥 기간 후보 충돌
- 기간 미확정
- 한쪽 절대기간 후보의 의미 연결 필요
- 비교기간 미확정

모델이 기간을 제안해도 다음 조건을 모두 만족해야 성공한다.

1. 모델이 제시한 문맥 근거 문구가 기사 원문에 그대로 존재한다.
2. 근거 문구에 기간 표현과 Claim 지표 연결어가 함께 존재한다.
3. 기사 작성일과 동일한 결정론 기간 변환기로 같은 목표기간이 계산된다.
4. 비교 Claim은 비교기간도 결정론적으로 재현돼야 한다.

따라서 모델이 그럴듯한 날짜를 만들더라도 원문 인용·지표 연결·날짜 재계산 중 하나가
실패하면 기존 HOLD가 유지된다.

## 5. 해석 경계

이번 결과는 다음을 증명한다.

- 구조화 LLM을 규칙 HOLD 뒤에 제한적으로 연결할 수 있다.
- 모델 제안을 결정론 수치·문맥 검증으로 거부할 수 있다.
- 동일 339건에서 원자 분리 전제조건 통과가 30건에서 222건으로 증가했다.

그러나 다음을 증명하지는 않는다.

- 222건의 자식 Claim이 독립 Gold와 모두 일치한다는 것
- KOSIS 공식 통계표·좌표·공식값 연결이 완료됐다는 것
- 최종 사실 판정 정확도가 향상됐다는 것

부모→자식 Gold와 문맥기간 Gold가 없으므로 정확도는
`NOT_EVALUABLE_STAGE_SPECIFIC_GOLD_MISSING`으로 유지한다. 1번 성공과 2번 성공은 서로
다른 단계 지표이므로 합쳐서 정확도라고 말하지 않는다.
