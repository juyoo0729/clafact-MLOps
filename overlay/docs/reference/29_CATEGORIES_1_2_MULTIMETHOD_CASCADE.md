# 1번·2번 다중방법 Claim 구조화와 KOSIS 재진입 경계

## 목적

1번 문맥 보완 256건과 2번 복수 Claim 분리 339건을 한 모델이나 완화된 규칙으로 강제 통과시키지 않고,
여러 제안 방법 뒤에 동일한 결정론적 검사를 두는 방식으로 다시 실행했다. 이 문서는 운영 coverage,
Gold 정확도, KOSIS 조회 완료를 서로 다른 결과로 기록한다.

## 사용한 방법

2번은 `rule_current`, `rule_v2`, `rule_v3_paren`, `rule_v3_enum`, `rule_v3_clause`,
`rule_ensemble`의 6개 오프라인 방법을 같은 339건에 적용했다. 이후 기존 성공을 보존하면서
OpenAI 구조화 출력과 HCX 구조화 출력을 HOLD에만 순차 적용했다.

모델 출력은 다음 조건을 모두 통과할 때만 채택했다.

1. 자식 목표 수치가 부모 원문에 존재한다.
2. 부모 수치가 자식 전체에서 누락되지 않는다.
3. 자식마다 검증할 목표 수치와 `target_value_role`이 하나로 정해진다.
4. 단위 없는 모델 목표값은 원문에서 일치하는 단위 포함 수치가 하나일 때만 정규화한다.
5. 검사를 통과하지 못하면 기존 HOLD를 유지한다.

1번은 기사 작성일, 앞·뒤 문맥, Claim을 함께 제공하되, 제안 기간을 그대로 믿지 않았다. 근거 문구가
기사 문맥에 그대로 있고 Claim의 지표와 연결되며, Python 기간 변환기가 같은 기간을 계산할 때만
채택했다.

## 같은 고정 입력에서의 결과

| 대상 | 초기 | OpenAI 뒤 | 최종 | 해석 |
|---|---:|---:|---:|---|
| 1번 성공 | 126/256 | 136/256 | 136/256 | OpenAI +10, HCX +0 |
| 2번 성공 | 30/339 | 222/339 | 235/339 | OpenAI 뒤 HCX +13 |
| 2번 안전 자식 Claim | - | 596 | 627 | 원문 수치·단일 목표값 검사 통과 |

규칙 6종의 개별 엄격 성공은 16~29건이었고, 6종 성공 합집합도 29건이었다. 따라서 이번 고정 입력에서는
규칙 종류를 더하는 것만으로 큰 개선이 생기지 않았으며, 모델 제안 뒤 같은 Hard Guard를 적용하는
cascade가 coverage 개선에 더 효과적이었다.

1번 HCX 보조 실행은 추가 성공이 없었다. 재시도 없는 최종 실행에서 88건은 내용상 HOLD, 3건은 API
오류였다. 이 실패도 삭제하지 않으며 `NOT_IMPROVED`로 기록한다. 다음 개선은 모델을 하나 더 붙이기보다
기사 본문에서 Claim과 같은 지표를 가진 기간 근거 문장을 먼저 선택하는 방법이어야 한다.

## 12슬롯을 유연하게 만드는 원칙

12개 항목 전체가 항상 채워져야만 다음 단계로 보내는 방식은 보조 정보가 없는 Claim까지 조기에 차단할
수 있다. 그러나 필수 항목 자체를 없애면 잘못된 KOSIS 좌표를 자동 선택할 위험이 있다. 따라서 슬롯을
다음 세 등급으로 분리한다.

- 필수 Gate: 지표, 목표값, 단위, 기준기간, 지역 또는 대상, `target_value_role`
- 조건부 필수: 비교기간, 비교방향, 계산식, 주기
- 보조: 기사 표현, 동의어, 문맥 근거, 검색 힌트

조건부 필수 항목은 Claim 유형상 필요할 때만 요구한다. 빈 보조 슬롯은 HOLD 원인이 아니라 검색 점수의
감점 근거로 사용한다. 필수 Gate가 빠진 Claim은 계속 HOLD로 남긴다.

## KOSIS로 넘기는 다음 한 가지 실험

이번 실행의 KOSIS 재조회는 0건이다. 이유는 새로 통과한 문맥·자식 Claim을 아직 12슬롯으로 다시
구조화하지 않았기 때문이다. `KOSIS 통과율`을 높이기 위한 다음 실험은 다음 순서로 제한한다.

1. 최종 성공 1번 Claim과 2번 안전 자식 Claim을 같은 Claim ID로 12슬롯에 재구조화한다.
2. 필수/조건부/보조 Gate와 `target_value_role`을 검사한다.
3. 통과 Claim만 로컬 KOSIS 구조표 registry에서 후보를 찾는다.
4. 표·항목·지역·기간·단위 좌표를 Hard Guard로 확정한다.
5. 좌표가 확정된 Claim만 공식값을 호출하고 응답 해시·조회 시각·출처를 기록한다.

이 순서를 지키지 않고 현재 627개 자식 Claim을 곧바로 KOSIS에 보내면, Claim 분리 개선과 통계표 탐색
실패가 다시 섞여 원인을 설명할 수 없다.

실제 다음 입력은 `build_r2_multimethod_reentry_queue.py`로 고정한다. 이 도구는 1번 성공 136건과
2번 안전 자식 627건, 총 763건에 대해 이미 확보된 슬롯, 부족한 R3 필수 슬롯, 원문 목표값,
`target_value_role`, 재진입 상태와 KOSIS 차단 사유를 JSONL로 기록한다. 구조화 추출이나 KOSIS API를
대신 수행하지 않으므로 이 대기열 자체를 12슬롯 성공으로 보고하지 않는다.

## 평가 경계

이번 수치는 결정론적 안전검사를 통과한 운영 coverage다. 같은 Claim ID의 독립 부모→자식 Gold와
기간 Gold가 없으므로 분리 F1, whole-claim exact, 12슬롯 정확도는
`NOT_EVALUABLE_STAGE_SPECIFIC_LINKED_GOLD_MISSING`이다. KOSIS 조회가 0건이므로 표 정확도와 공식값
정확도도 보고하지 않는다.
